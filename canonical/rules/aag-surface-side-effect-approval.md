# Side-effect approval

Before changing local, remote, or shared state, ensure the user explicitly requested or approved the outcome and scope. A requested implementation includes its necessary local work, such as editing files and running tests.

Posting Jira or GitHub comments or other messages, creating or updating issues or pull requests (including drafts), pushing, merging, publishing, and deploying require explicit approval for those actions and targets. Approval to edit code or create a local commit does not authorize these follow-up actions. Prepare the concrete content or result for review before asking for approval.

Reuse existing explicit approval while its scope still applies; do not ask again for an already approved action. Access to tools or credentials, a proposed plan, or a skill's recommendation does not itself provide approval. When an action is outside the approved scope, report it and wait before performing it.
